Editor — Feature Reference

← Main Window

This page is a reference for the editor’s editing features. It deliberately skips things every modern text/code editor already does — open/save, cut/copy/paste, plain undo/redo, basic find, syntax highlighting, line numbers, plain multi-line indent — and focuses on features that are either uncommon elsewhere or work a little differently here. Running SQL/PL/SQL against a database is a separate topic — see Main Window and Quick Query and others.

Most commands below are reachable from the menus and the editor context menu, and every shortcut can be changed from Tools > Settings > Keymap. However, that requires manual edit of custom.keymap and switching to it in settings. The shortcuts shown here are the ones SQLTools ships with by default.

Selection modes

Unlike most editors, which only support a single “stream” selection (optionally with a secondary rectangular-selection modifier key), this editor has two persistent, switchable selection modes that stick until you change them:

  • Stream Selection (F8) — normal contiguous text selection.
  • Column Selection (Ctrl+Shift+F8) — a persistent rectangular/column selection mode; every subsequent mouse/keyboard selection is a rectangular block until switched off.
  • Toggle Selection Mode (Ctrl+Q, B) — quick switch between the two.
  • In addition to the sticky mode above, holding Alt while selecting with the mouse, or Alt+Shift while selecting with the arrow keys, temporarily forces column mode for that one selection without changing the sticky mode — see Entering column selection with Alt below.

Column selection here is not only a transient Alt+drag — it is also a documented, sticky editor mode that affects clipboard, indent, case-conversion, and auto-surround operations uniformly (see Column / block editing).

Convenience selection commands: Select Word (Ctrl+W), Select Line (Ctrl+L).

Clipboard & line operations

Beyond plain cut/copy/paste:

  • Cut & Append (Ctrl+Shift+X) / Copy & Append (Ctrl+Shift+C) — append the current cut/copy to the existing clipboard content instead of replacing it, letting you accumulate several non-contiguous fragments into one paste.
  • Cut / Copy / Delete Bookmarked Lines (Ctrl+K, X / Ctrl+K, C / Ctrl+K, D) — operate on the set of all currently bookmarked lines in the document at once, regardless of contiguity (see Bookmarks below).
  • Duplicate Line or Selection (Ctrl+K, Q).
  • Delete to End of Word (Ctrl+Delete) / Delete Word Back (Ctrl+Backspace) and Delete Line (Ctrl+Y).

Navigation, scrolling & bookmarks

  • Scroll Up / Down / To Center without moving the caret (Ctrl+Up, Ctrl+Down, Num 5) — scrolls the viewport while keeping the cursor position in the buffer, useful for glancing at surrounding code.
  • Toggle Bookmark (Ctrl+F2), Next / Previous Bookmark (F2 / Shift+F2), Remove all Bookmarks (Ctrl+Shift+F2).
  • Numbered (“random access”) bookmarks 0–9 — Set Random Bookmark (Ctrl+Shift+0…9) and Get Random Bookmark (Ctrl+0…9) let you pin up to 10 named jump points and return to any one directly by number, instead of cycling sequentially through all bookmarks.
  • Find Match (Ctrl+]) / Find Match & Select (Ctrl+Shift+]) — goes well beyond plain brace/parenthesis/bracket matching. It also understands SQL and PL/SQL language pairs and jumps the caret (optionally extending the selection to cover everything in between) between:
    • SQL statement keywords — SELECT / FROM / WHERE (and other clause keywords of the same statement);
    • PL/SQL block/control keywords — IF / ELSIF / ELSE / END IF, CASE / WHEN / END CASE, LOOP / END LOOP, BEGIN / END, and similar paired constructs.
    This makes it a quick way to jump around the structure of a statement or a PL/SQL block without a mouse, the same way brace-matching lets you jump around nested code in other languages.
  • Go To (line/column) (Ctrl+G).
  • Open file under cursor (Ctrl+K, F) — treats the token under the caret as a file reference and opens it directly, handy for jumping to @script.sql includes or referenced file paths without leaving the keyboard.

Find, replace & find-in-files

  • Find (Ctrl+F) / Replace (Ctrl+H) open a modeless dialog that does not block the editor: it searches as you type with a live match count and highlighted matches, and can search the selection, the current document or all open editor windows. Mark All bookmarks every matching line. See Find and Replace.
  • Find Next / Previous (F3 / Shift+F3) and, notably, Find Selected Next / Previous (Ctrl+F3 / Ctrl+Shift+F3) — instantly search for the next or previous occurrence of the currently selected text without opening the Find dialog.
  • Find In Files (Ctrl+Shift+F) — grep-style search across multiple files with file-mask filtering and recursive directory search, with results shown in a dedicated output panel (double-click a hit to jump to it). See Find in Files.

Auto-closing & auto-surrounding pairs

Full details, including the columnar variant: Auto-closing and Auto-surround. Two related but distinct features, both configurable in Tools > Settings > Editor > Editing:

  • Auto-close: typing an opening character — (, [, {, ', " — automatically inserts its matching closer and leaves the caret between them. A setting restricts this to only trigger when the character to the right is whitespace/end-of-line, to avoid unwanted closing when typing next to existing text.
    • Overtype/skip-over: typing the same closing character that was just auto-inserted moves the caret past it instead of inserting a duplicate, and this caret move is not recorded on the undo stack.
    • Undo: the auto-inserted closer is its own undo step, separate from the opener, so a single Undo removes only the auto-inserted character.
    • Suppressed automatically inside quoted strings and while in overtype/insert mode; not suppressed inside comments.
  • Auto-surround: typing an opening character while text is selected wraps the selection with the matching pair (( ), [ ], { }, ' ', " ", ` `) instead of replacing it, and re-selects the wrapped text. Works with a column/rectangular selection too — every line of a block gets its own pair. The whole operation is a single Undo step.

Indentation & whitespace

  • Indent / Undent Selection (Ctrl+I / Ctrl+U) — multi-line block indent/outdent, tab-width aware.
  • Untabify Selection (Ctrl+K, U) — convert tabs to spaces.
  • Tabify Selection (All) (Ctrl+K, T) vs. Tabify Selection (Leading only) (Ctrl+K, L) — the distinction between tabifying the whole selection versus only leading indentation whitespace is not offered by most editors, which usually only do leading-whitespace tabify.
  • Trim Leading Spaces (Ctrl+K, O), Trim Trailing Spaces (Ctrl+K, R), Trim Excessive Spaces (Ctrl+K, P) — the “excessive spaces” variant collapses runs of interior spaces, which goes beyond the usual trailing-whitespace trim most editors provide.
  • Smart auto-indent — the third "Auto indent" mode on the Editor → Categories settings page, beside None and Default. Where Default copies the leading whitespace of the line above, Smart reads the PL/SQL block structure around the caret and indents the new line relative to that line: pressing Enter after BEGIN, IF … THEN, ELSIF, ELSE, LOOP, WHEN … THEN, EXCEPTION, a CASE statement or expression, an IS/AS definition header or an unclosed bracket steps one level in, and END, END IF, END LOOP, END CASE, a closing bracket or a statement-terminating semicolon steps back out. The level is applied to the line above, so a line you have already misaligned keeps its offset until you run Format SQL. Inside a continued string literal or block comment the new line is treated as literal content and simply keeps the indentation above it. Pressing Enter in the middle of a line is understood too: the text after the caret keeps its place, the new line is indented from that tail's own first keyword rather than from the level the line above left open, and a line ending on ||, a comma, or an arithmetic or comparison operator — or a continuation line starting with one, which is how Format SQL wraps a long expression — is continued one level deeper. A condition wrapped across lines follows the same rule: each top-level AND / OR of an IF, ELSIF or WHILE sits one level under the header keyword, and the THEN or LOOP that ends it comes back to the header's own level. Indenting also happens while you type: Enter can only place the line it creates, so typing the last character of END, ELSE, ELSIF, EXCEPTION or WHEN on a line that is one level too deep — or a closing bracket that begins its line — pulls that line back to the level it belongs at and moves the caret with it. One Ctrl+Z removes the character and restores the previous indentation. A language with no smart rules behaves exactly as Default does, so selecting Smart is safe everywhere. No shipped category selects it.

Case & text transformation

  • Lowercase (Ctrl+Shift+Down), Uppercase (Ctrl+Shift+Up), Capitalize (Ctrl+K, A), Invert Case (Ctrl+K, I) — the “Invert case” option (toggle each letter’s case) is less commonly found than plain upper/lower/capitalize.
  • Normalize Keyword (Ctrl+K, N) — reformats identifiers and keywords under the caret or selection to the casing convention configured for the recognized language (e.g., normalizing SELECT/select/Select to one canonical form), driven by the language’s keyword table rather than blind case conversion.
  • Datetime Stamp (Ctrl+T) — inserts a formatted current date/time at the caret.

Column / block editing

Because Column Selection is a first-class, sticky mode (see Selection modes), a full set of column-aware operations builds on it:

  • Insert/Fill Columns… (Ctrl+K, B) — insert or fill a rectangular block of text down a column selection.
  • Insert Number… (Ctrl+K, M) — insert an auto-incrementing sequence of numbers, one per line, into a column selection — useful for quickly numbering a list of rows/lines without a macro.
  • Column Left / Center / Right Justify (Ctrl+K, Y / Ctrl+K, V / Ctrl+K, W) — align text within a column block.
  • Clipboard, indent, case-conversion and auto-surround commands described elsewhere all operate per-line across a rectangular block when column mode is active.
Entering column selection with Alt

You rarely need to switch the sticky Column Selection mode explicitly: holding Alt while selecting — with either the mouse or the keyboard — auto-switches into column mode for that selection.

  • Mouse: Alt + drag starts a rectangular (column) selection instead of a normal stream selection.
  • Keyboard: Shift + arrow keys extend a selection as usual; adding Alt (i.e. Alt+Shift+Arrow) while doing so likewise turns the selection into a rectangular block. This is the standard way to make a column selection purely from the keyboard — grow the block by rows/columns with Alt+Shift+Up/Down/Left/Right (or Alt+Shift+Page Up/Page Down, etc.).
  • Releasing Alt does not cancel the column selection already in progress; it stays a column selection until you clear it or start a new one.
Typing into a multi-line column selection

Once you have a non-empty, multi-line column (rectangular) selection and you type a regular character, the editor does not replace the whole block with one character — it types that character on every selected line simultaneously, at the same column, producing a multi-caret-like editing effect:

  • If the block is a real rectangle (more than one column wide): the selected columns on every line are replaced by one copy of the typed character per line.
  • If the block is a zero-width column selection (e.g. you pressed Alt+Shift+Down without moving right, giving you a multi-line caret with nothing actually highlighted): the typed character is inserted (not overwritten) on every line at that column, and the caret advances one column to the right afterward — the classic “type once, appears on every line” behavior.
  • The whole keystroke is a single Undo step, covering every affected line at once.
  • Tab / Shift+Tab with an active column selection indents/outdents every selected line by one tab stop in lockstep, instead of inserting a literal tab character into the block.
  • Typing an opening bracket or quote with a column selection active auto-surrounds every line of the block in the pair (see Auto-closing & auto-surrounding pairs) rather than replacing the block.

This behavior is what makes rectangular selections useful as a lightweight substitute for “multiple cursors” found in newer editors — you don’t get independent carets with independent navigation, but simultaneous same-column typing, deleting, indenting, case-conversion, and surrounding across many lines is fully supported. This behavior can be turned off in Tools > Settings > Editor > Block if you prefer the block to simply be overwritten instead.

Text sorting & formatting utilities

  • Sort… (Ctrl+K, S) — sort selected lines (dialog-driven; supports options such as case sensitivity/order).
  • Join Lines (Ctrl+K, J) / Split Line… (Ctrl+K, K) — merge selected lines into one, or split a line by a delimiter/column with a dialog for choosing where to break.
  • Remove Blank Lines (Ctrl+K, G) vs. Remove Excessive Blank Lines (Ctrl+K, H) — remove all blank lines, or only collapse consecutive runs of blank lines down to a single one (preserving intentional paragraph-style spacing).
  • Format SQL (Ctrl+K, E; Ctrl+Shift+K, E to adjust settings first) — invokes the built-in SQL/PL/SQL formatter on the current selection or statement. See SQL Formatter and SQL Formatter — PL/SQL.

Comments

  • Comment Line (Ctrl+>) / Uncomment Line (Ctrl+<) — language-aware line commenting (uses the correct line-comment token for the current language, e.g. -- for SQL) rather than a hardcoded token.

Templates & auto-text

Expand Template (Ctrl+Space) — expands a short keyword typed at the caret into a predefined block of text (a lightweight code-snippet/live-template system). Create Template (no default shortcut — assign one under Tools > Settings > Keymap, where it is listed as Edit.CreateTemplate) — makes a new one from the selected text. The Snippets pane (Alt+5) lists every template for browsing and mouse-driven insertion.

Full details — how much of a keyword you must type, where the caret lands afterwards, what the two-tone badge means, and how to hide a template from the pane — are on the Templates and Snippets Pane pages.

Encoding & line-ending handling

  • Viewing the current encoding vs. converting to a different encoding are two separate menu groups: one reflects/sets how the file is interpreted (ANSI / OEM / UTF-8 / a specific codepage), the other actually re-saves the file content in a new encoding — including UTF-8/UTF-16 with-or-without-BOM variants and an open-ended codepage list, which is broader than what most editors expose directly from a menu. Neither group has a default keyboard shortcut.
  • File line ending style: Windows / Unix / Old Mac — explicit conversion including the legacy classic-Mac CR-only line ending, rarely still offered elsewhere. No default keyboard shortcut.

Visual aids / display toggles

Beyond the usual syntax highlighting and line numbers:

  • Syntax Gutter (Ctrl+Q, Y) and Ruler (Ctrl+Q, U) toggles.
  • Column Markers (Ctrl+Q, M) — vertical guide line(s) at configured column positions (e.g. to flag 80-column overflow).
  • Indent Guide (Ctrl+Q, G) — vertical lines tracing indentation levels.
  • Visible Spaces (Ctrl+Q, I) — render whitespace characters.
  • Line Numbers (Ctrl+Q, L).

File & document behaviors

  • Read Only toggle at the session/document level (Ctrl+D, O) — the view is rendered in a distinct, “locked” look while the document is protected.
  • Per-file Properties… (Ctrl+Q, F) — inspect/override file-level settings (e.g., encoding, line-ending, tab width) independent of the global editor settings (Ctrl+Q, P).
  • Multi-step operations (templates, auto-surround, reformatting) are grouped so they collapse into a single user-facing Undo step instead of requiring many presses of Undo.

Drag & drop

Internal drag-to-move / drag-to-copy (hold Ctrl while dragging to copy) of selected text within and between editor views, plus drop support for files dragged in from Explorer.

The data grid also supports dragging selected cells or column headers and dropping them into the editor — see Data Grid — Drag and Drop.

Autocomplete (database objects)

Ctrl+Shift+Space opens a completion popup. Unlike typical IDE code-completion, this list is not a keyword or language-syntax completion — it is available only while connected to a database, and only ever lists database objects: schemas, tables/views, columns, and packages/procedures (with their parameters), resolved contextually:

  • After a schema name and a dot → objects of that schema.
  • After a table/view name or alias and a dot → that table’s columns (with alias-resolution logic to figure out which table an alias refers to).
  • After a package name and a dot → the package’s procedures/functions with parameters.
  • For table/view columns specifically, you can multi-select several columns (Space, Ins, or Ctrl+Left-Click) in the order you want them, and insert all of them at once.

See Autocomplete for the full behavior, alias-resolving logic, and settings. Without an active database connection this popup has nothing to offer — it does not fall back to keyword or word-based completion.

Code outlining

The Code Outline panel (Alt+4) shows a structural outline of the current SQL/PL/SQL document (procedures, functions, packages, blocks), letting you navigate directly to a symbol’s declaration. See Code Outline.

Code folding

PL/SQL code blocks — program units, BEGIN … END, IF / CASE / LOOP blocks, multiline statements and runs of comment lines — can be collapsed to a single line ending in a […] marker, from the folding gutter (the −/+ boxes between the line numbers and the text), the left-margin context menu, or the Edit > Outlining submenu. The default shortcuts are Ctrl+M chords: Ctrl+M, S collapses the region around the caret, Ctrl+M, E expands it, Ctrl+M, A and Ctrl+M, X collapse and expand the whole document. Hiding lines never loses text: find, print, copy and caret jumps still work on the full document and reveal folded regions as needed. Folding is on by default — see Code Folding for the complete command list, settings and limitations.
