What's new in 2.5

Editable Data Grid

The data grid can now write to the database: F2 changes a cell, Ctrl+F2 inserts a row, Ctrl+Shift+F2 duplicates the current one, Ctrl+Enter posts it, Esc discards it and Ctrl+Del deletes the row. Writes are addressed by ROWID against the single table the query reads, so a join or a result set with no ROWID column leaves the grid read-only.

A cell edit or row delete now locks its row first, with NOWAIT, so a row another session holds uncommitted or has already deleted is reported immediately rather than waited on. Neither refusal changes the grid, which keeps showing what the database has.

JSON and Excel Workbook Export

The data grid exports to JSON, pretty-printed or compact, and straight to a native Excel workbook (.xlsx) in which numbers stay numbers, a DATE or TIMESTAMP stays a real date Excel can sort and filter, and a NULL becomes an empty cell. "Open with Excel" now writes that workbook instead of a CSV.

Snippets Pane

A dockable pane (Alt+5) that lists the editor's code templates as cards, so a snippet can be picked and inserted at the caret instead of its keyword being typed. Each card's badge shows the keyword that expands it and the minimum number of characters that must be typed first; a card shown dimmed belongs to another language class than the active document's, and cannot be expanded where the caret is.

Redesigned Find & Replace

The editor Find/Replace dialog is modeless now: it no longer blocks the editor, searches as you type with a live match count and highlighted matches, and can search in the selection, the current document or all open editor windows.

Auto-closing and Auto-surround

Including PL/SQL-aware auto-surround

Smart auto-indent for PL/SQL

A third "Auto indent" mode that reads the block structure around the caret, so Enter after BEGIN, IF…THEN, LOOP, WHEN…THEN, EXCEPTION, CASE or an unclosed bracket indents one level in and END, END IF, a closing bracket or a statement-terminating semicolon steps back out. Enter in the middle of a line indents from the text after the caret, a wrapped expression continues one level deeper — including an IF or WHILE condition split across AND / OR, whose THEN or LOOP comes back to the header's level — and typing the last character of END, ELSE, ELSIF, EXCEPTION or WHEN pulls a line that is one level too deep back to where it belongs. Opt-in per category; every language without smart rules keeps behaving as the Default mode.

Code Outline

Code Folding

The editor can collapse PL/SQL blocks — procedures, IF/LOOP blocks, whole SELECT statements, comment blocks — to a single line ending in a [...] marker, from the folding gutter or the Edit → Outlining menu (Ctrl+M chords).

What's new in 2.0

Autocomplete

SQLTools provides autocomplete with proper alias-resolving logic.

Unicode support

The program partially supports Unicode/UTF now. The editor works with European languages w/o any issues but eastern characters are not supported mainly because the Windows monospaced fonts are actually not fixed-width for those code pages. The data grid, on other hand, should handle any texts.

New docking window framework

The control panels like "File Panel", "History", "Open Files", "Object Viewer" can be docked more easily, as well as stacked in tabs. Additionally panels can "Auto hide" in the docking mode. The window tab control "Workbook" is more functional and nicer than in the version 1.9.

Re-implemented "Find In Files"

The external grep program was replaced with the internal implementation which is faster and more functional. See Find in Files for more details.
