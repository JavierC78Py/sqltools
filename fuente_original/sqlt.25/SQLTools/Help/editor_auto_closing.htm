Auto-closing brackets and quotes

When you type an opening bracket or quote character, the editor automatically inserts the matching closing character right after the cursor, leaving the cursor positioned between the pair so you can keep typing the contents.

Supported pairs:

OpeningClosing
()
[]
{}
""
''

Auto-closing is suppressed while overtype (Insert/Overtype) mode is active, and is suppressed for quote characters when the cursor is already positioned inside a quoted string — see Suppression inside strings below.

Typing over the auto-inserted closer

If the character immediately to the right of the cursor is a closing character that was auto-inserted earlier on the same line, and you type that same closing character again, the editor simply moves the cursor past it instead of inserting a duplicate. This lets you type (1+2) naturally, typing the closing ) yourself without ending up with (1+2)).

Undo behavior

Pressing Ctrl+Z immediately after an auto-closed pair was inserted removes only the auto-inserted closing character, leaving the opening character in place and the cursor where the pair was opened. Skipping over an auto-closer by typing it yourself (see above) is a caret move only and is not recorded on the undo stack.

Auto-surround a selection

When there is an active (non-empty) selection and you type an opening bracket or quote character, the editor wraps the selected text with the matching pair instead of replacing it. Typing the closing bracket of a pair (), ], }) does the same thing — the selection is wrapped in the complete pair, exactly as if the opening bracket had been typed. The original selection is preserved, now covering the wrapped text.

Supported pairs: ( ), [ ], { }, ' ', " ", ` `.

Example: selecting text and typing ( — or ) — produces (text), with text still selected.

A single Ctrl+Z undoes the whole action, restoring both the original text and the original selection.

Auto-surround in column (block) selections

Auto-surround also works with a column (block) selection: when the selected block is not zero-width, typing an opening character — or its closing counterpart — surrounds every line of the block with the matching pair at the block's edges, and the original block selection is preserved, shifted to account for the inserted opening character. A single Ctrl+Z undoes the whole block operation.

A zero-width column block (a plain column-mode caret with no selected width) keeps the editor's normal column-insert behavior and is not affected by auto-surround.

PL/SQL-aware auto-surround (escaped quotes and q-quote literals)

In documents whose language supports Oracle alternative quoting (PL/SQL), auto-surround of a normal (stream) selection understands Oracle string-literal syntax. This behavior is controlled by the PL/SQL-aware auto-surround setting (on by default); while it is on, it takes the place of the two "Auto-surround…" settings for the characters described below — those characters surround the selection even when the corresponding older setting is off. Column (block) selections are not affected and keep their standard behavior described above, as do all other characters and all languages without alternative quoting.

  • Typing ' surrounds the selection with single quotes, first doubling every single quote inside it so the result is a valid PL/SQL string literal: selecting it's and typing ' produces 'it''s', with the escaped text left selected. When the selection contains no single quotes, the result is identical to the standard quote surround ('abc').
  • Typing { or [ surrounds the selection with an Oracle alternative-quoting (q-quote) literal instead of the plain bracket pair: selecting abc and typing { produces q'{abc}'; typing [ produces q'[abc]'. Typing the closing bracket } or ] does the same as typing the opening one. The original text is left selected in all cases.

The q-quote form is produced only when it yields a valid literal. If the selection starts inside a string, or the selected text itself contains the closing sequence (}' for a typed {, ]' for a typed [), the editor falls back to the standard bracket-surround rules: a plain {…} / […] pair when "Auto-surround with brackets" is on, or the ordinary replacement of the selection by the typed character when it is off. The escaped-quote surround is likewise suppressed while the selection starts inside a string — see Suppression inside strings.

As with the standard surround, a single Ctrl+Z undoes the whole operation and restores both the text and the selection.

Suppression inside strings

To avoid interfering with quote characters that are part of SQL or PL/SQL string literals, both auto-closing and auto-surround of quote characters are suppressed while the cursor is positioned inside a string — including a case where the quote kind typed does not match the enclosing string's quote kind. Inside comments, both features behave exactly as they do on plain text.

Settings

These options are available on Tools > Settings…, Editor page, in the "Auto-closing and auto-surround" group:

Setting Default Description
Auto-close brackets and quotes On Master on/off switch for auto-closing brackets and quotes.
Auto-close only before whitespace Off When enabled, the closing character is inserted only if the character to the right of the cursor is whitespace or end of line; otherwise the closing character is inserted regardless of what follows.
Auto-surround with quotes On Enables wrapping a selection with matching quote characters.
Auto-surround with brackets On Enables wrapping a selection with matching bracket characters.
PL/SQL-aware auto-surround On In PL/SQL files: typing ' around a selection doubles embedded quotes; typing { or [ produces a q'{…}' / q'[…]' literal. For those characters this setting replaces the two auto-surround settings above; it does not affect column (block) selections or other languages. See PL/SQL-aware auto-surround.
