Code Folding

Code folding lets you temporarily hide blocks of code in the PL/SQL editor — procedure bodies, IF and LOOP blocks, whole SELECT statements, comment blocks and more. A collapsed block shrinks to a single line with a [...] marker at its end, so you can concentrate on the part of the file you are working on. Hiding lines never changes the file: the full text is always there for editing, searching and printing.

Folding is driven by the same syntax analysis as the Code Outline pane, and it is switched on by default.

Turning Folding On and Off

Two ways to switch folding:

  • Tools → Settings… → Editor → Navigation and Outline, group Code folding: check Enabled.
  • Right-click anywhere in the editor's left margin (the line-number gutter) and toggle Folding Enabled in the context menu. The item carries a check mark while folding is on.

Because folding comes from the outline parser, it requires PL/SQL keyword navigation to be enabled on the same settings page. Files without recognisable PL/SQL structure (plain SQL*Plus scripts, text documents) show no fold boxes.

The Folding Gutter

When folding is on, a narrow band appears between the line numbers and the text. Every foldable block gets a small box in this band:

  • Click a − box to collapse the block. The box turns into a + and the hidden lines are replaced by a [...] marker at the end of the block's first line.
  • Click a + box, or anywhere on the [...] marker, to expand the block again.

The block around the caret is lightly tinted in the gutter so you can see at a glance which region the fold commands will act on. This tint is purely visual and can be switched off (see Settings below) without affecting folding itself.

Commands and Shortcuts

All folding commands are on the Edit → Outlining submenu and in the gutter context menu. The default shortcuts are two-key chords: press Ctrl+M, release, then press the second key.

Command Shortcut What it does
Collapse Current Region Ctrl+M, S Collapse the fold region around the caret
Expand Current Region Ctrl+M, E Expand the fold region around the caret
Toggle Current Region Ctrl+M, M Collapse or expand the fold region around the caret
Expand Current Subtree Ctrl+M, J Expand the region around the caret and everything nested inside it
Collapse All Ctrl+M, A Collapse every fold region in the document
Expand All Ctrl+M, X Expand every collapsed region in the document
Toggle All Ctrl+M, L Expand all folds, or collapse all when nothing is folded
Collapse to Level 1 Ctrl+M, 1 Collapse every region; only top-level anchors stay visible
Collapse to Level 2 Ctrl+M, 2 Collapse regions nested two levels or deeper
Collapse to Level 3 Ctrl+M, 3 Collapse regions nested three levels or deeper

The commands that act on the region around the caret are only available when the caret is inside a foldable region; the whole-document commands are available as soon as the file contains any. The shortcuts shown are the defaults of the standard keymap; a different keymap layout can be selected on the Editor → General settings page.

What Can Be Folded

  • Packages, package bodies, and the procedures, functions and types declared in them
  • Standalone CREATE [OR REPLACE] PROCEDURE / FUNCTION / TYPE BODY units
  • BEGIN … END blocks, including anonymous DECLARE blocks
  • IF, CASE, FOR and WHILE LOOP blocks that span several lines
  • Multiline SQL statements: SELECT (including its clauses), INSERT, UPDATE, DELETE, MERGE, OPEN … FOR, CREATE TRIGGER
  • Blocks of consecutive comment lines

Single-line constructs, expressions and SQL*Plus commands do not fold. Blocks nested very deeply (more than four levels) may not offer a fold box; everything above that depth still folds normally.

Working with Folded Text

  • Nothing is lost. Collapsing only hides lines; the document keeps its full content. Printing and print preview always include the hidden lines.
  • Search reaches hidden text. Find, Replace and bookmark jumps work on the whole document, and a hit inside a collapsed region expands it automatically so you can see the result.
  • The caret is never hidden. If a command would put the caret on a hidden line, that region expands first.
  • Selections span folds. A selection that reaches over a collapsed region includes the hidden lines: copy, cut and delete act on the full range.
  • Editing keeps folds. Typing inside a region adjusts the fold as the outline is reparsed; regions stay collapsed where possible.

Settings

Both switches are in Tools → Settings… → Editor → Navigation and Outline, group Code folding:

Enabled
Master switch for code folding. On by default. Turning it off expands every hidden line immediately; turning it back on restores the fold boxes with all regions expanded. The same switch is available as Folding Enabled in the gutter context menu.

Highlight the current region
On by default. Tints the gutter next to the region around the caret so it is easy to see which region the fold commands will affect. This is a visual aid only: switching it off does not disable any folding command.

Notes

  • If a file has syntax errors, fold regions may be missing or approximate while the parser recovers; fixing the syntax restores them.
  • Folding also works in read-only files — collapsing does not modify the document.
