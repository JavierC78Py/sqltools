Regular Expressions

Both the editor Find and Replace dialog and Find in Files accept regular expressions when the Regular expression check box is on. SQLTools uses the POSIX Extended syntax (the one used by egrep and awk), implemented by the Boost.Regex library, with a few Boost-compatible extensions noted below. With the check box off, the search text is always matched literally, whatever characters it contains.

Syntax basics

Every character matches itself except the special characters . [ ] { } ( ) \ * + ? | ^ $:

Construct Meaning
. Any single character.
^ / $ Start / end of line (searching in SQLTools is line-based).
* Zero or more repetitions of the preceding atom, e.g. ab*c.
+ One or more repetitions, e.g. [0-9]+.
? Zero or one repetition, e.g. colou?r matches color and colour.
{n}, {n,}, {n,m} Exactly n, at least n, or between n and m repetitions, e.g. ^[0-9]{4,6}$.
(...) Marked sub-expression (group): limits the scope of the operators and captures text for back-references and for the replace references \1…\9.
| Alternation: cat|dog matches either word. Group it as ab(d|ef).
\1…\9 Back-reference: matches the same text as group n matched, e.g. ^(a*)[^a]*\1$ matches aaabbaaa. (A Boost extension - standard POSIX Extended has no back-references.)
\x Escapes a special character: \. matches a literal dot, \\ a literal backslash.

Quantifiers are greedy (they match as much text as possible), and when there is more than one way to match, the leftmost-longest match wins - the POSIX rule, not Perl's first-alternative-wins rule. So a|ab against the text ab matches ab, and there are no lazy quantifiers such as *?.

Character sets

  • [abc] - any one character of the set; [a-z] - any character of the range.
  • [^abc] - any character not in the set.
  • [[:name:]] - a named character class inside a set. The most useful names: alnum, alpha, blank, cntrl, digit, graph, lower, print, punct, space, upper, word, xdigit. Example: [[:alpha:]_][[:alnum:]_]* matches an identifier.
  • All of the above can be combined: [[:digit:]a-c_].

Escape sequences

Beyond the POSIX basics, Boost.Regex supports these escapes (SQLTools inherits them):

Escape Meaning
\a \e \f \n \r \t \v Bell, Escape (0x1B), form feed, new line, carriage return, tab, vertical tab.
\d \s \w A digit, a white-space character, a word character - the same as [[:digit:]], [[:space:]], [[:word:]]. Upper case \D \S \W match the complements.
\b \B A word boundary / not a word boundary. Inside a character set [\b] means backspace.
\< \> Start / end of a word.
\xdd \x{dddd} \0ddd The character with the hexadecimal / octal code, e.g. \x41 is A.
\cx An ASCII control character, e.g. \cI is tab.
\Q…\E Everything between \Q and \E is matched literally.
\ + other Any other escaped character matches itself, e.g. \@ is @.

The Expression Builder

The button next to the Find what box (in both dialogs, enabled with the Regular expression option) inserts the commonly used constructs at the cursor position:

Inserts Meaning
\t Tab character
. Any single character
* / + Zero or more / one or more
^ / $ Beginning / end of line
[] / [^] Any one character in the set / not in the set
| Or
\ Escape a special character
([a-zA-Z0-9]) Alpha-numeric character
([a-zA-Z]) Alphabetic character
([0-9]) Decimal digit
([0-9a-fA-F]+) Hexadecimal digits
([a-zA-Z_$][a-zA-Z0-9_$]*) C-identifier
(([0-9]+\.[0-9]*)|([0-9]*\.[0-9]+)|([0-9]+)) Rational number
(("[^"]*")|('[^']*')) Quoted string

The Replace with box of the editor dialog has its own builder button that inserts the group references described below.

Group references in Replace

With Regular expression on, the Replace with text of the editor Find and Replace dialog can refer to what the groups of the pattern matched:

Reference Meaning
\0 The whole matched text (Find What Text).
\1…\9 The text matched by the n-th parenthesised group (Tagged Expression n), counted by opening parentheses. A reference to a group that did not participate in the match inserts nothing.

Example: find ([[:alpha:]]+)=([[:digit:]]+) and replace with \2 /* \1 */ turns width=10 into 10 /* width */. The replacement text must be a single line - carriage returns are not supported.

The "Backslash expressions" option

This option is independent of the regular-expression one. When checked, the backslash sequences in the typed search/replace text are converted to the corresponding control characters before the search runs: \a \b \f \n \r \t \v \' \" \\ \? and \ddd, where ddd is a decimal character code of up to 3 digits (e.g. \65 is A). It lets you search for tabs and other unprintable characters without knowing their regex escapes. Note that with Regular expression also on, \digit in the Replace with text stays a group reference.

Good to know

  • Searching is line-based in both the editor and Find in Files: ^/$ mean line start/end and a pattern can never match across a line break.
  • Match whole word only works together with regex patterns - only matches at word boundaries are reported.
  • An invalid pattern reports "Regular expression error" when a search is started explicitly; the editor's search-as-you-type preview simply shows no match while the pattern is incomplete (e.g. an unclosed ( or [a-).
  • The full syntax reference of the underlying engine is the POSIX Extended Regular Expression Syntax chapter of the Boost.Regex documentation.
