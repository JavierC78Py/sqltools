Snippets Pane

The Snippets pane is a browsing list of every template SQLTools knows about. Where expanding a template requires you to already know its keyword, the pane answers the opposite question: what is there, and what does each one produce? Each template is a card showing its name, the keyword that triggers it, and the text it expands to. You can insert a card into the editor with the mouse, or copy it.

Opening the Pane

Choose View → Snippets (Alt+5 by default). It is a dockable pane like the Database Browser or Code Outline, so it can be floated, tabbed alongside another pane, or docked to any edge. The same command hides it again.

The Status Line

A line at the bottom of the pane always tells you what you are looking at, so a filtered list never passes for the whole collection:

Anatomy of a Card

Each card has three parts:

  • The name — the template's descriptive label, on its own line, drawn in the standard interface font rather than the editor's code font. A card name is chrome, not content.
  • The badge — the trigger keyword, in a tinted pill on the same line as the name, and in the code font. Two-tone; see below.
  • The body — the text the template inserts, in the editor's code font, shown only while the card is expanded.

Click the arrow, or anywhere on the name line, to expand or collapse a card. Expand all and Collapse all are on the context menu. Whichever cards you had open, and how far you had scrolled, survive a refresh — the pane does not throw you back to the top when the template collection changes underneath you.

Reading the Badge

The badge is the part of the pane worth understanding, because it answers a question the keyword on its own cannot: how much of this do I actually have to type?

A badge is drawn in two tones. The bold, dark leading part is the minimum you must type. The pale remainder is optional — it completes the keyword, but you never have to reach it. Matching is by prefix, so anything from the bold part up to the whole keyword works.

CardBadge readsTyping this is enough
Select select s
Create or Replace create cr
Exception exception exc
If Else ife ife — all of it

An all-bold badge means the whole keyword is required. That is not a rendering fault. It appears when a template's minimum length equals the length of its keyword, so there is no optional remainder left to draw pale. If Else is stored with keyword ife and a minimum of 3; the all-bold badge is the pane correctly saying "no shortcut here, type all three".

Why ife needs all three. The PL/SQL set also contains if with a minimum of 1. If If Else also had a minimum of 1, typing i would be ambiguous between two templates. Its minimum of 3 keeps them apart. For the full rule — including what happens when several templates match at once — see Expanding a Template.

Which Templates You See

By default the pane shows only the language of the file you are editing, so a PL/SQL script lists the PL/SQL templates and nothing else. Two context-menu toggles widen the view:

  • Show all languages — lists every template in every category, grouped under a language heading so you can still tell them apart. Useful when you are looking for something and cannot remember which set it belongs to.
  • Show excluded — adds back the templates that have been hidden from the pane.

The language filter gives way automatically when it would show you nothing. If the file you are editing has no templates of its own, or every one of them is excluded while Show excluded is off, the pane drops the filter rather than presenting an empty list that looks like a broken feature. The status line tells you which case you are in.

Excluded Cards Appear Dimmed

A template can be opted out of the pane without being disabled — it keeps expanding on its keyword exactly as before, it just stops appearing here. The reason is that the two audiences differ: a one-word expansion such as number → NUMBER is useful at the caret and is noise in a browser, where it costs a whole card to say almost nothing.

With Show excluded on, those templates reappear dimmed, so they are visibly not part of the normal list but are still reachable. Select one and use Exclude from snippets on the context menu to bring it back. See Exclude From Snippets.

Inserting a Snippet

Select a card and press Ctrl+Enter, or double-click it, to insert the template's text at the caret of the active editor. The insertion goes through exactly the same path as expanding the keyword by hand, so the caret lands in the position the template author marked rather than at the end of the block.

Insertion needs an editor to insert into. With no document open nothing is inserted and the status line reads No editor to insert into. The pane reports this in place rather than in a dialog, because it is a state you can see and fix for yourself.

Bare Enter does not insert. It expands or collapses the card, as does Space. In a list of things you can open, Enter opening one is the stronger reading, and inserting into your script from a bare Enter would be a surprise the first time it happened. Use Ctrl+Enter or a double-click to insert.

Copying and Dragging

Copy (Ctrl+C) puts the selected template's text on the clipboard, and you can also drag a card straight into the editor. Either way the clipboard carries a private marker alongside the text, which lets the editor re-indent the block to the column you dropped it at instead of leaving it flush-left the way an ordinary paste would. Pasting the same text from another application carries no marker and is inserted verbatim.

Managing Templates From the Pane

The pane is not read-only. From the context menu you can Add template…, Edit template… and Delete template…, each opening the same Template Form the settings page uses. A new template goes into the language of the card you have selected, or into the language of the file you are editing when nothing is selected; if neither is available the status line says No language to add a snippet to. Delete template… asks for confirmation, because it removes the entry for good.

Exclude from snippets toggles the opt-out described above for the selected card; it carries a check mark while the card is excluded, so the mark tells you which way the click will go rather than only that a click will do something.

Keeping the Pane Up to Date

The pane watches the template collection and rebuilds itself when it changes, so editing a template through the settings page, or editing templates.xml by hand and returning to SQLTools, is reflected without you having to ask. A rebuild keeps the cards you had expanded and your scroll position.

Refresh forces a rebuild immediately. It is rarely needed, but it is there for the case where you have changed the file behind SQLTools' back.

If you invoke a command on a card whose template has since been deleted or had its identity changed, the pane does not act on the wrong entry. It refreshes and reports Snippet has changed - list refreshed on the status line.

Changes made in the pane are written to the settings immediately, which is why Exclude from snippets needs no OK button.
