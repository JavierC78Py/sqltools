Templates

A template is a short keyword that expands into a block of text you would otherwise have to type. Type sel in the editor, press Ctrl+Space, and you get a complete SELECT statement with the caret already sitting where you need to keep typing.

Templates serve two different jobs, and it is worth keeping them apart:

  • Expansion at the caret — what this page covers. The keyword you type in the editor, the rule that decides whether it expands, and where the caret ends up.
  • Browsing in the Snippets pane — covered on its own page. A searchable list of every template, showing what each one expands to, that you can insert from with the mouse.

Both read the same collection, so a template you add is immediately available to both. A template can also be hidden from the pane while still expanding on its keyword — see Exclude from snippets.

What Ships With SQLTools

SQLTools comes with 31 templates across 8 languages: PL/SQL, C++, Java, SQR, Shell, Text, XML and PERL. Only the templates belonging to the language of the file you are editing are offered, so a PL/SQL script sees begin, cursor and exception, and nothing from the Java set. You can edit or delete any of the shipped entries and add your own.

Expanding a Template

Type the beginning of a keyword and choose Text → Expand Template (Ctrl+Space by default). The keyword is replaced by the template's text and the caret moves to the position the template author marked.

Two conditions have to hold before a template expands:

  1. What you typed must be the beginning of the template's keyword. Typing sel matches select; typing sel does not match update.
  2. What you typed must be at least the template's minimum length. This is the Min length field, and it exists so that a one- or two-letter keyword does not fire before you have said which template you mean.

Because the first condition is a prefix test, you never have to type the whole keyword. With select at a minimum length of 1, any of s, se, sel or select expands it.

Minimum length decides who wins when keywords overlap. The shipped PL/SQL set contains if (minimum 1), ife (minimum 3) and ifeif (minimum 4). Typing if expands If, because ife and ifeif have not reached their minimum yet. Typing ife expands If Else. Typing ifeif expands If Else If. Each longer keyword is protected from the shorter one by its own minimum, which is why the values are not all 1.

When Expansion Shows a List Instead

Sometimes more than one template starts with what you typed, and expanding the first one would be a guess. The setting Always show Autocomplete list if there is an alternative on the Templates settings page decides what happens:

  • Unchecked (the shipped default) — the first template that matches is expanded immediately.
  • Checked — if anything else also starts with what you typed, expansion is handed to Autocomplete instead, which lists the candidates and lets you pick. Nothing is inserted until you choose.

This setting is stored per language, so PL/SQL can behave differently from Java.

Where the Caret Lands

A template is only half useful if the caret ends up at the bottom of the text it just inserted. Each template records a caret position, and you set it by typing a caret marker — ^ — into the template's text where you want to land.

For example, the shipped If template is stored as: 

IF ^ THEN
END IF;

The ^ is not part of the inserted text. It is removed when you save, its position is remembered, and expanding the template leaves the caret between the two spaces of IF THEN, ready for the condition. Reopening the template in the editor puts the ^ back where it was, so you can see and move it.

A template with no marker leaves the caret at the very start of the inserted text.

Creating a Template From a Selection

The quickest way to add a template is to write the text once, in the editor, and then keep it. Select the text and choose Text → Create Template. The Template Form opens with the Text field already filled in from your selection, so all you have to supply is a name and the keyword that will bring it back.

There is no default shortcut for Create Template. If you use it often, bind one under Tools → Settings → Keymap, where the command is listed as Edit.CreateTemplate. Its companion Edit.ExpandTemplate is what Ctrl+Space is bound to.

The Template Form

The Template Form is where a single template is edited. It opens from Create Template, and from the Add… and Edit… buttons on the settings page and in the Snippets pane. The dialog can be resized, which is worth doing before pasting in a long block of SQL.

FieldWhat it does
Name The label shown in the settings list and on the card in the Snippets pane. Purely descriptive — it plays no part in matching, and two templates may share a name.
Keyword What you type to trigger the template. Matching is by prefix, so the keyword only has to start with what you type.
Min length How many characters of the keyword you must type before it will expand. Raising it is how you stop a short keyword from firing too eagerly, and how the if / ife / ifeif family coexists. Setting it equal to the keyword's full length means the whole keyword must be typed.
Exclude from snippets Hides the template in the Snippets pane while leaving expansion untouched. See below.
Text The block that gets inserted. Use ^ once, anywhere, to mark where the caret should land — see Where the Caret Lands.

Exclude From Snippets

The two audiences for a template genuinely differ. A one-word expansion such as number → NUMBER is valuable at the caret and is noise in a browser, where it takes up a card to say almost nothing. Exclude from snippets opts a template out of the pane without disabling it: it keeps expanding on its keyword exactly as before, it simply stops appearing in the list.

Excluded templates are not lost. Turn on Show excluded in the Snippets pane and they reappear, dimmed, so you can still reach them and un-exclude them. The settings page also has an Excluded column marking the same entries.

The Templates Settings Page

Tools → Settings… → Editor → Templates lists every template for the language chosen in the Category drop-down at the top. The page opens on the language of the file you were editing, so from a PL/SQL script you land on the PL/SQL set.

The list has four columns:

ColumnShows
Namethe descriptive label
Keywordwhat you type to trigger it
Min lengthhow much of the keyword is required
Excluded marked for templates hidden from the Snippets pane

Add…, Edit… and Delete… below the list open the Template Form. Double-clicking a row is the same as Edit….

The Always show Autocomplete list if there is an alternative checkbox beneath the list controls the behaviour described above, for the category currently selected.

Where Templates Are Stored

Templates live in templates.xml in the SQLTools settings folder, grouped by language. The file is plain XML and safe to edit by hand or to share between machines, though SQLTools rewrites it whenever you change a template through the UI. The structure is: 

<OpenEditor>
  <Templates MajorVersion="1" MinorVersion="1">
    <Language Name="PL/SQL" AlwaysListIfAlternative="0">
      <Template Name="If" Keyword="if" MinLength="1"
                CurLine="0" CurPos="3">IF  THEN&#13;&#10;END IF;</Template>
      …
AttributeMeaning
Language/@Namethe category the group belongs to
Language/@AlwaysListIfAlternative 1 to defer to Autocomplete when several templates match
Template/@Namethe label
Template/@Keywordthe trigger text
Template/@MinLengthrequired prefix length
Template/@CurLine, @CurPos where the caret lands, zero-based, relative to the inserted text
Template/@Uuidstable identity; see the note below
Template/@ExcludeFromSnippets 1 to hide the template from the pane
Editing the file by hand? Leave out Uuid and SQLTools will generate one the first time it loads the entry, and leave out ExcludeFromSnippets to mean "not excluded". Both are written back on the next save. Do not copy a Uuid between two templates — it is what tells them apart.

Copying a Template for Re-indenting

When you copy a template out of the Snippets pane, or drag it into the editor, the clipboard carries a private marker alongside the text. The editor recognises it on paste and re-indents the block to the column you dropped it at, instead of leaving it flush-left the way a plain copy would. Pasting the same text from another application has no marker and is inserted verbatim. This is handled for you; there is nothing to configure.
